# Lock-Free Stack на Go: конкурентная структура данных без Mutex

Практическая реализация **lock-free стека на Go**, которая показывает, как несколько горутин могут безопасно работать с одной структурой данных без использования `sync.Mutex`.

Проект будет полезен разработчикам Go, которые хотят разобраться в **конкурентном программировании, атомарных операциях, CAS (Compare-And-Swap)** и принципах построения неблокирующих структур данных.

## Что вы получите от проекта

Изучая этот проект, вы сможете:

* понять, как работает **lock-free алгоритм** на практике;
* разобраться, зачем нужны атомарные операции в конкурентном коде;
* увидеть применение `atomic.Pointer` в Go;
* понять принцип работы **CAS (Compare-And-Swap)**;
* изучить классическую реализацию **стека Трайбера (Treiber Stack)**;
* посмотреть, как несколько сотен горутин одновременно изменяют одну структуру данных;
* использовать реализацию как основу для собственных экспериментов с конкурентными структурами данных;
* лучше понимать, чем lock-free подход отличается от решений на `sync.Mutex`.

Проект ориентирован не только на демонстрацию готового алгоритма, но и на **изучение того, как устроены неблокирующие структуры данных внутри**.

## Что реализовано

### Treiber Stack

Стек построен на основе связного списка и использует атомарный указатель на вершину (`head`).

Основные операции:

* `Push` — атомарно добавляет элемент в стек;
* `Pop` — атомарно извлекает элемент из стека.

Для изменения вершины используется CAS-цикл. Если другая горутина успела изменить стек, операция повторяет попытку с актуальным состоянием.

## Как работает Push

Упрощённо операция добавления элемента выглядит так:

1. Горутина получает текущее значение `head`.
2. Создаёт новый узел.
3. Новый узел связывается с текущей вершиной.
4. Выполняется CAS: вершина заменяется на новый узел только в том случае, если она не изменилась.
5. Если другая горутина изменила вершину раньше, CAS завершается неудачей и операция повторяется.

Так несколько горутин могут конкурировать за изменение структуры данных, не используя обычную блокировку.

## Зачем изучать lock-free подход

Обычный mutex заставляет горутины ждать освобождения критической секции.

Lock-free алгоритмы используют атомарные операции и позволяют избежать традиционной блокировки общего ресурса. Это делает их особенно интересными для изучения при работе с высококонкурентными системами.

При этом lock-free программирование сложнее обычного mutex-подхода: необходимо учитывать гонки, корректность CAS-циклов и особенности работы с памятью.

Этот проект позволяет увидеть эти принципы на относительно небольшой и понятной структуре данных.
